# חוזה · חוט plan-supporter-import
**תפקיד:** תכנון ייבוא-תומכות — הצלבת שורות-הקובץ מול הקיימות לפי שם מנורמל:
שם קיים ⇒ עדכון ({id, row}), שם חדש ⇒ הוספה. כפילויות בתוך הקובץ מתמזגות
לרשומה אחת (הראשונה גוברת, השאר ממלאות חוסרים דרך fillEmpty — כולל קיבוץ-
עדכונים פר-id, תיקון 9.8: קובץ-עסקאות עם שורות רבות לאותו תורם קיים אוסף
את כל ההיסטוריה במקום ששרדה רק השורה האחרונה). שורות ללא שם (אחרי trim)
מדולגות. טהור — לא נוגע ב-store.
**שקעים (חוק-1 — קריאות-השכן הוזרקו כפרמטרים):**
- ‏normName(s) ⇒ מחרוזת — נרמול-שם להשוואה (במקור: נרמול-חיפוש עברי + הסרת
  כל הרווחים). נקרא על שם-קיים ועל שם-שורה.
- ‏fillEmpty(a, b) ⇒ שורה — מיזוג שדות לא-ריקים מ-b לתוך a (‏a גובר כשקיים);
  ‏hist מצטרף ([...a.hist, ...b.hist]) — כל עסקאות התורם בקובץ נאספות.
**קלט:** rows (שורות-ייבוא, לכל אחת name) · existing (תומכות {id, name}) ·
שני השקעים. **פלט:** { updates: [{id, row}...], inserts: [row...] }.
**דוגמאות מחייבות (עם normName=נרמול-רווחים+lowercase ו-fillEmpty האמיתי):**
1. שם קיים: rows=[{name:'דוד לוי', phone:'050'}], existing=[{id:'s1', name:'דוד לוי'}]
   ⇒ updates=[{id:'s1', row:{name:'דוד לוי', phone:'050'}}], inserts=[].
2. התאמת-נרמול: name:'דוד  לוי' (רווח כפול) תואם 'דוד לוי' הקיים ⇒ עדכון, לא הוספה.
3. קיבוץ פר-id (9.8): שתי שורות לאותו תורם קיים, לכל אחת hist של עסקה אחת
   ⇒ עדכון יחיד שבו row.hist באורך 2 (ההיסטוריה לא אבדה).
4. מיזוג הוספות: [{name:'רות', phone:'', email:'a@b'}, {name:'רות', phone:'052', email:''}]
   ⇒ inserts יחיד {name:'רות', phone:'052', email:'a@b'} (הראשונה גוברת, השנייה ממלאת).
5. שורה בלי שם: name:'  ' ⇒ מדולגת (לא עדכון ולא הוספה).
**מוצא:** maor/src/components/supporters/lib.ts:598-636 (‏planSupporterImport).
חולץ כלשונו; ‏normName (שם:360) ו-fillEmpty (שם:520, פרטי) הפכו לשקעים.
