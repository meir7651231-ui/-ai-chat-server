# חוזה · חוט collections-csv-rows
**תפקיד:** שורות-CSV של כל ריקוני קופות-הצדקה — שקיפות מלאה: כל ריקון שנרשם
מיוצא. שורה ראשונה = כותרות: תאריך · רכז · קופה · <מונח-משפחה> · סכום · מבצע.
כל ריקון ⇒ ‏[date, שם-רכז, '#'+num, שם-משפחה, amount, שם-מבצע]; ישות חסרה ⇒ ''.
**שקעים (חוק-1 — קריאת-השכן הוזרקה כפרמטר):**
- ‏termOf(config, key, fallback) ⇒ המונח הארגוני (במקור: lib/config). נקרא רק
  כש-config מועבר; בלי config — ה-fallback ('משפחה') כלשונו.
**קלט:** db (עם tzBoxes/tzCoordinators/tzCampaigns/families) · config? · השקע termOf.
**פלט:** מערך שורות ‏(string|number)[][], תמיד עם שורת-כותרות.
**דוגמאות מחייבות:**
1. ‏db ריק (tzBoxes=[]) ⇒ שורה אחת בלבד:
   ‏['תאריך','רכז','קופה','משפחה','סכום','מבצע'] (בלי config — fallback).
2. קופה ‏{num:3, coordinatorId:'c1', famId:'f1'} עם ריקון
   ‏{date:'2026-08-01', amount:120} כשרכז c1='רבקה' ומשפחה f1='כהן' ⇒
   שורה 2 = ‏['2026-08-01','רבקה','#3','כהן',120,''].
3. ריקון עם ‏campaignId:'p1' כשמבצע p1='חנוכה' ⇒ עמודה אחרונה 'חנוכה'.
4. רכז/משפחה שלא נמצאו (מזהים זרים) ⇒ '' בעמודות שם-הרכז ושם-המשפחה.
5. עם config ושקע ‏termOf שמחזיר 'לקוח' ל-'entity.family' ⇒ הכותרת הרביעית
   'לקוח' (המונח הארגוני גובר על ה-fallback).
6. קופה עם 2 ריקונים ⇒ 2 שורות-נתונים (שורה פר-ריקון).
**מוצא:** maor/src/components/tzedaka/lib.ts:281-301 (‏collectionsCsvRows,
CONNECT — תדפיסים/CSV). חולץ כלשונו; השכן termOf הפך לשקע (חוק-1).
