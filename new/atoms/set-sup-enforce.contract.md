# חוזה · חוט set-sup-enforce
**תפקיד:** חישוב ערך **מצב אכיפת-התומכים** החדש בשכבת-הנתונים (פאזה-2,
dormant): כשדלוק — כל מסמך-תומך נדחף עם ‏skey plaintext ‏(=forWho) ועובד/ת
מוגבל/ת מושך/ת בשאילתת ‏`where skey in […]` (Rules דוחים list לא-מסונן).
הדגל הנכנס עובר **כמות-שהוא** — הוא הערך שהצד-הדוחף/המושך ישאל דרך
‏supEnforceActive.
**גלגול-המצב (חוק-5):** במקור הערך הושם למשתנה-המודול ‏supEnforceOn; ההשמה
היא **חיווט-קופסה** — האטום רק מחשב (מעביר) את הערך החדש. ברירת-המחדל
הבטוחה ‏supEnforceOn=false ("off-by-default ⇒ אף קוד לא מדליק עד פאזת-ההפעלה
⇒ ביט-זהה להיום — בלי skey, בלי סינון") שייכת אף היא לקופסה.
**קלט:** ‏on — boolean. **פלט:** אותו boolean — ערך-המצב החדש.
**דוגמאות מחייבות:**
1. ‏setSupEnforce(true) ⇒ ‏true — האכיפה הודלקה (פאזת-הפעלה).
2. ‏setSupEnforce(false) ⇒ ‏false — כיבוי מפורש (זהה לברירת-המחדל הדורמנטית).
3. הערך עובר כמות-שהוא, בלי כפייה (ההשמה במקור verbatim; טיפוס-boolean מובטח
   ב-TS אצל הקורא): ‏typeof הפלט 'boolean' כששולחים boolean.
4. דטרמיניסטי וחסר-מצב: קריאות חוזרות עם אותו קלט ⇒ אותו פלט, אפס דליפה
   בין קריאות.
**מוצא:** maor/src/lib/cloud.ts:122-125 (‏setSupEnforce — "נקבע מ-connectCloud/
applyCloudDoc לפי supEnforceOn(config) — עדיין לא מחווט, פאזה-5").
