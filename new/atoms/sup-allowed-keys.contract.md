# חוזה · חוט sup-allowed-keys
**תפקיד:** ערכי שאילתת-ה-‎`where('skey','in',…)`‎ לעובד/ת מוגבל/ת בחלוקת-התומכים:
הייעודים המותרים — מנוקים (trim), ריקים מסוננים, כפולים מאוחדים, נחתכים ל-29 —
ועליהם המפתח-המשותף בסוף. ‏Firestore מגביל ‎in‎ ל-30 ערכים ⇒ 29 ייעודים + המשותף.
דטרמיניסטי: סדר-הקלט נשמר (הופעה ראשונה קובעת).
**שקעים (חוק-1 — קבוע-שכן הוזרק כפרמטר):**
- ‏sharedKey — המפתח-המשותף (בקוד-המקור: הקבוע ‏SHARED_SUP_KEY‏ = ‏'_shared_'‏
  באותו קובץ). האטום רק מצרף אותו אחרון — עיוור לערכו.
**קלט:** ‏allowed: string[]‏ · השקע sharedKey. **פלט:** ‏string[]‏ (אורך ≤ 30).
**דוגמאות מחייבות:**
1. ‏(['חינוך','רווחה'], '_shared_') ⇒ ‏['חינוך','רווחה','_shared_'] (3 ערכים, המשותף אחרון).
2. ‏([' חינוך ','חינוך','','רווחה'], '_shared_') ⇒ ‏['חינוך','רווחה','_shared_']
   (trim ⇒ הכפול אוחד; הריק סונן).
3. ‏35 ייעודים שונים p1..p35 ⇒ אורך-הפלט 30: ‏p1..p29 + ‏'_shared_' (חיתוך ל-29).
4. ‏([], '_shared_') ⇒ ‏['_shared_'] (אין ייעודים — רק המשותף).
5. ‏(['ב','א'], '_shared_') ⇒ ‏['ב','א','_shared_'] (סדר-הקלט נשמר — אין מיון).
