# חוזה-הדאטה של המלאי + מפת-מקומות-התצוגה (2.9.2026)

> **המקור:** בניית SchoolOS·מלאי לפי THE-WAY. הכרעת-בעלים 2.9: *"ברגע שיהיה ספק או מחיר —
> הוא צריך להיות מקום בו הוא יוצג. תתעד, ותחתיו לתקן לפי הדרך."*
> כלומר המסך = **נגזרת-טהורה של חוזה-הדאטה**; לכל שדה **מקום שמור ומחווט**; שדה קיים ⇒ מוצג,
> שדה חסר ⇒ לא-מרונדר (אפס-זיוף §20-ג). זה מבחן-הקונכייה (חוק-7): "מחק-והעלה-קטלוג-חדש עדיין עובד".

## המטרה
**"אף פריט קריטי לא ייגמר לפני שנספיק לחדש אותו."**

## חוזה-הדאטה של פריט-מלאי (`_InvData.items`)
| שדה | טיפוס | חובה? | מקור-אמת |
|------|-------|-------|-----------|
| `name` | String | חובה | שם-הפריט |
| `cur` | int | חובה | מלאי-נוכחי (ביד) |
| `target` | int | חובה | רמת-יעד בריאה |
| `rate` | double | חובה | קצב-צריכה יומי |
| `lead` | int | חובה | זמן-אספקה (ימים) |
| `supplier` | String | **אופציונלי** | ספק |
| `price` | int | **אופציונלי** | מחיר ליחידה (₪) |

**נגזרות טהורות** (לא נשמרות — מחושבות): `daysLeft = cur/rate` · `mustOrderIn = daysLeft − lead` ·
`band` (2=הזמן-היום · 1=הזמן-בקרוב ≤חלון · 0=בטוח) · `qty = target − cur`.

## מפת-מקומות-התצוגה (איזה אטום מגלם כל חלקיק)
| חלקיק | אטום-מדף | תנאי-רינדור |
|--------|----------|-------------|
| ימים-עד-ריקון **מול** זמן-אספקה (b1·b2·b3) | `NeonBars` | פריט-פעיל (band≥1) |
| מרווח-ביטחון / הפס (b4) | ה-band ⇒ tone | תמיד |
| **מלאי-נוכחי** (a1) | `StatusChip` tone0 "`N ביד`" | תמיד |
| **קצב-צריכה** (a2) | `StatusChip` tone0 "`R/יום`" | תמיד |
| **ספק** (d3) | `StatusChip` tone0 "`🏭 …`" | **רק אם `supplier != null`** |
| **מחיר** (d4) | `StatusChip` tone0 "`₪ … ליח׳`" | **רק אם `price != null`** |
| כמות-להזמנה (c2) | `StatusChip` tone2/3 | פריט-פעיל |
| מועד (c3) | `StatusChip` tone2/3 "היום / תוך N" | פריט-פעיל |
| עדיפות (c4) | מיון daysLeft עולה | תמיד |
| **לבצע: "סמן הוזמן"** (d1) | `SoftButton` tone1 | פריט-פעיל, לא-הוזמן |
| **מצב "הוזמן ✓"** (d2) | `StatusChip` tone1 + `SoftButton` "בטל" | פריט-מסומן-הוזמן |
| בטוח-ושקט | `StatRow` | band==0 |

**המקום-השמור:** שורת-facts (Wrap של StatusChip) נבנית מ**איטרציה על שדות-החוזה** —
`if (s['supplier'] != null) StatusChip(...)` · `if (s['price'] != null) StatusChip(...)`.
הוספת `supplier`/`price` לרשומה ⇒ השבב מופיע **בלי שינוי-קוד**. הסרה ⇒ נעלם. זה ה"מקום".

## סגירת-הלולאה (d1·d2)
`_Inventory` = StatefulWidget עם `Set<String> _ordered` (מצב=חיווט לגיטימי, THE-WAY צעד-4).
"סמן הוזמן" ⇒ `setState(_ordered.add)` ⇒ הפריט הופך ל"הוזמן ✓" **ויוצא ממונה דורשי-הזמנה** ⇒
המסך מפסיק לנדנד (פותר הזמנה-כפולה/אובדן-אמון). "בטל" מחזיר. התנהגות-אמת מקומית, **לא דאטה-מזויפת**.

## מה נשאר מחוץ-לגבול (ובמכוון)
- **ביצוע-הזמנה-אמיתי** (שליחה לספק/סליקה) — דורש שרת/אינטגרציה ⇒ מעבר לגבול; "סמן הוזמן" הוא
  התיעוד-המקומי בלבד.
- **דאטת-ספק/מחיר אמיתית לכל הפריטים** — לא ממציאים ערכים (§20-ג). החוזה **מוכן**; הערכים מגיעים
  מהזנת-הלקוח. בדוגמה הנוכחית רק חלק מהפריטים נושאים supplier/price — כדי להוכיח את המקום-השמור
  בשני הכיוונים (קיים ⇒ מוצג · חסר ⇒ שקט).
- **מגמת-צריכה / ספייק** (e2) · **הזמנה-מרוכזת-לפי-ספק** (e3) — roadmap; דורשים היסטוריית-צריכה שאין.

## הפירוק המלא (חלקיקים · נוכח/חסר לאחר התיקון)
A מצב-נוכחי: a1 ✅ · a2 ✅ · a3(target) ⚠️ נגזר ל-qty, לא-מוצג-ישיר.
B הקרבה: b1·b2·b3·b4 ✅.
C החלטה: c1·c2·c4 ✅ · c3 ⚠️ טקסט-מועד בלי תאריך-יעד.
D פעולה+לולאה: d1 ✅ · d2 ✅ · d3 ✅(מותנה) · d4 ✅(מותנה).
E עומק: e1 ✅ (a1+a2 חשופים ⇒ הסיבה נראית) · e2 ❌ · e3 ❌.
