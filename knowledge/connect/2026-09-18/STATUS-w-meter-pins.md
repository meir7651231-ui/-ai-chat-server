## 2 · 🔴 ההעברה **אינה** מכאנית — שלוש סטיות, כל אחת בבייטים

ההערה בראש `meter-100.mjs` (שורות 25–29) הבטיחה: «הגוף שלמטה נכנס כבלוק
`if (METER) {…}` **אחרי בלוק-ברירת-המחדל**, והייבואים זהים». בדקתי לפני שהעתקתי,
כפי שהתבקשתי. שתי הטענות שגויות, והשלישית לא נאמרה כלל:

### 2.1 · «אחרי בלוק-ברירת-המחדל» ⇒ **קוד מת**

בלוק-ברירת-המחדל של `nl-smoke` יוצא **ללא-תנאי** (‏`nl-smoke.mjs:33-44`, לפני השינוי):

```js
if (!COMPILE) {
  …
  if (fail) { …; process.exit(1); }
  console.log('\n✅ רצפת-§22: כל המשפטים-החופשיים בונים אפליקציה');
  process.exit(0);          // ← כאן התהליך מת
}
```

‏`--meter` הוא `!COMPILE`, ולכן בלוק שממוקם **אחריו** לעולם לא היה נכנס להרצה.
שתי הדרכים לתקן: להוסיף `&& !METER` לתנאי-ברירת-המחדל (נגיעה בהתנהגות הקיימת), או
להקדים את הבלוק. **בחרתי להקדים** — `if (METER) {…}` לפני בלוק-ברירת-המחדל, ומסתיים
ב-`process.exit`. כך שורת-`if (!COMPILE)` נשארת בייט-זהה ו-`nlsmoke` לא הרגיש כלום.

### 2.2 · «הייבואים זהים» ⇒ **חסרים שלושה שמות**

| שם | היה ב-nl-smoke? | מה עשיתי |
|---|---|---|
| `resolveDart` | ❌ (רק `resolveFlutter`, `parseAnalyze`) | נוסף לייבוא-הקיים מ-`dart-bin.mjs` — **פותר אחד** (L111) |
| `scanUnits` · `scanOne` | ❌ (‏`behavior-plan.mjs` לא יובא כלל) | **ייבוא-דינמי בתוך הבלוק** |

הייבוא הדינמי אינו קישוט: ייבוא-סטטי היה גורר את `behavior-plan.mjs` (‏1,000+ שורות)
לכל ריצה של `nlsmoke` · `nlquality` · `nlcompile` — שלושה שערים שלא ביקשו אותו. עם
`await import(...)` בתוך `if (METER)`, מסלוליהם נטענים **בדיוק כמו קודם**.

### 2.3 · מה שלא נאמר: **ריצה חלקית דרסה את רשומת-הריצה-המלאה**

`--quick` (5 שניות) כתב על `knowledge/connect/2026-09-18/meter-100.json` — ה-JSON
ש-`--seal` קורא, וש-315 שורות-הפנקס של הריצה-המלאה חיות בו. נתקלתי בזה באימות של §1:
אחרי ריצת-`--quick` אחת נאלצתי `git checkout` כדי להחזיר את הפנקס.

`--seal` אמנם **מסרב** לרצפה חלקית (‏`if (S.quick || S.limit != null) exit 2`) — השומר הזה
נכון וקיים — אבל הראיה כבר נמחקה, ובקלון-טרי בלי git היא לא הייתה חוזרת.
