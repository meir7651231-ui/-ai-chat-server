## 5 · 🔴 באג-אמת שהפירוק חשף: ‏`exprId` כפול ⇒ הוכחה-חלולה

**מה שראיתי:** בשלוש המטרות שהניבו צרכים, הצורך `predicate.record<שדה>Over<K>` קיבל
`proven: true` בתוכנית, ו-**הוכחת-ההרכבה נפלה** (`dart run --enable-asserts` על
`gen_goal_*_proof.dart`). הפער בין בורר-שמוכיח ל-קוד-שמורכב הוא בדיוק ה«ירוק-החלול»
שהדוקטרינה אוסרת, ולכן חפרתי עד הסיבה ולא הסתפקתי ב«הדוגמאות חלשות».

**הסיבה, בבייטים:** הצורך מצהיר גם `consts:["'date'", "90"]` וגם `entity:"Donation"`.
‏`CONSTS` נבנה מ-`need.consts` **ועוד** `schemaKeys(entity)` — ול-Donation יש שקע בשם
`date`. אותו ליטרל נכנס פעמיים ⇒ **שני עצים שונים עם אותו `exprId`**. ‏`evalInterp`
ממפתח תוצאות לפי `id`:
```js
for (const t of trees) out[t.id] = { ok: 0, total: nEx, … };           // logic-proof.mjs:234
… const e = out[trees[+m[1]].id]; if (m[3] === '1') e.ok++;            // logic-proof.mjs:235
```
שני מדדי-`ok` של **שני עצים** מצטברים לרשומה **אחת**, ו-`total` נשאר `nEx`. שני עצים
שכל אחד 2/4 נקראים **4/4**, והשער `r.ok === r.total` נפתח.

`hokRecordedThisMonth` מחזיר `false` לכל ארבע הדוגמאות (‏`sp['hok']` חסר ⇒ `_falsy` ⇒
`return false`) — אומת גם ב-Dart וגם בתאום-ה-JS. כלומר «הוכח» אטום שלא עונה לאף דוגמה.

**המדידה שאומתה על אותו צורך, לפני/אחרי:**
```
$ BP_DEBUG=1 BP_WANT="hokRecordedThisMonth(p0,'date',now,p0)" \
  node machtzev/generator/behavior-plan.mjs --needs one6.json --out /dev/null
לפני:  want … evaluated {"ok":4,"total":4,"unknown":0,"vals":["false","false","false","false"]}
אחרי:  want … evaluated {"ok":2,"total":4,"unknown":0,"vals":["false","false","false","false"]}
       [values] dup-exprid 4911          ← בעומק-2, באותו צורך יחיד
אחרי (עומק 2): want … not-generated      ← המועמד-החלול אינו מועמד
```
‏**4,911 זוגות-מועמדים** התמזגו בצורך אחד — זו תקלה מערכתית, לא מקרה-קצה.

**התיקון (שני חלקים, שניהם ב-`behavior-plan.mjs`):**
1. `CONSTS` עובר דדופ לפי הליטרל — הצהרה כפולה של אותו שם-שדה אינה שני שקעים.
2. **מגן-קשיח:** דדופ המועמדים לפי `exprId` לפני `evalInterp`, עם `dbg('dup-exprid', n)`.
   כך התמזגות-`ok` אינה יכולה לחזור גם אם מקור-כפילות חדש ייווצר.

‏`vals` שחוזרים כמחרוזות (`"false"` ולא `false`) הם הטביעה של אותה תקלה: `_v` עושה
`jsonEncode(jsonEncode(r))`, וה-`vals` של העץ השני דרסו את של הראשון.

**מה שלא נגעתי בו:** `logic-proof.mjs` עצמו. ניתן לחסום את המחלקה גם שם (לזרוק על
`id` כפול במקום למזג בשקט) — **הצעה לבעלים**, לא שינוי שעשיתי: `evalInterp` נקרא
ממסלולים נוספים ולא מדדתי אותם.

## 6 · בחירת-דוגמאות: מה שהמדידה אילצה
בגרסה הראשונה בחרתי 2 עוברים + 2 נופלים מ**קצות** ציר-הזמן. התוצאה (לדג'ר `anygoal1`):
```
g1.predicate.dateOver30  עבר  cmpGeStr(now,normId(p0))  weak=true ties=8 disc=2
```
`cmpGeStr(now, normId(p0))` הוא «‏now ≥ p0» — **מתעלם מהסף 30 לגמרי** ועובר דוגמאות
שכולן רחוקות מהסף. לכן הבחירה שונתה ל**קרובות-לסף משני צדיו + הקצוות**:
```
'2026-09-14' (36 ימים) ⇒ true · '2026-09-20' (30 ימים בדיוק) ⇒ false
```
