# Report — peruk21 empty-state text

## What was asked
Change the case-screen empty state in `machtzev/generator/specs-ds/peruk21.txt` from «אין תיקים עדיין» to «אין מכתבים פתוחים» without breaking anything.

## Why a plain spec edit was not enough
`specs-ds/peruk21.txt` is generated by `machtzev/generator/peruk.mjs --all` from the owner document `peruks/peruk-21.md`, and the `peruk` police gate requires the spec on disk to be byte-identical to the reader's output. The empty text came from one global value (`emptyText` in `peruk-lang.data.json`) stamped into all 28 peruk specs, so a hand edit would fail the gate and a global edit would change 27 other apps.

## What I did (per-document override seam, no hard-coded Hebrew in code)
- `peruk-lang.data.json`: added vocabulary key `"emptyKey": "ריק"`.
- `peruk.mjs`: the document preamble now accepts `ריק: <text>` (parsed into `doc.empty`); the `[ריק]` particle line uses `d.empty || P.emptyText`. Default behaviour for all other documents is unchanged.
- `peruks/peruk-21.md`: added the preamble line `ריק: אין מכתבים פתוחים`.
- Regenerated: `node machtzev/generator/peruk.mjs --all` (only `specs-ds/peruk21.txt` changed, one line; `peruk-index.json` and the other 27 specs are byte-identical), then `node machtzev/generator/app-ds.mjs -f machtzev/generator/specs-ds/peruk21.txt --name peruk21 --skin`.
- `node machtzev/pins-check.mjs --write` because `peruk.mjs` is a signature-pinned file.

Touched files: peruk-lang.data.json, peruk.mjs, peruks/peruk-21.md, specs-ds/peruk21.txt, particle-plan-peruk21.{json,md}, new/dart-gen-bs/gen_app_peruk21_px1.dart, new/dart-data-bs/auto/gen_app_peruk21_px1_content.dart, machtzev/pins.sha256. No git commit/push.

## How I know it works
- `git diff` of the generated Dart shows exactly two constant strings and one comment changed: `'אין תיקים עדיין'` → `'אין מכתבים פתוחים'` (same EmptyState atom, same wiring). No other output file of peruk21 changed.
- Gates run green in the working tree: `peruk.mjs --gate` (28/28 specs ≡ generator), `particles.mjs --gate` (448 particles, all wired, plan ≡ spec), `balagan-one.mjs --gate` (30 modules, moment identifier 30/30 — the new preamble line feeds the TF-IDF doc and did not disturb it).
- `node machtzev/police.mjs --fast`: 40 ran, 3 failed — `truth`, `index-complete`, `learn`. All three are pre-existing: I rebuilt a baseline copy of the tree with my nine files reverted to HEAD (via read-only `git show`) and the same three gates fail there with identical messages (`index-complete` names formula-fns/sort-cmp/spec-lang-doc.mjs which are HEAD files; `learn` fails on git blobs missing from this checkout). Re-measuring `truth` before and after applying my change gives a byte-identical TRUTH.md, so my change does not move it.
- Note on pins: the pins gate was already red at HEAD (LEARNINGS.md, gates.tsv, particles.mjs, render-ds.mjs, police.mjs stale; formula-fns.mjs and spec-lang-doc.mjs unsigned). The `--write` refresh absorbed those pre-existing drifts along with peruk.mjs; the pins gate is now green.
- Flutter/Dart are not installed, so no analyze/build was run; the change is string-literal only inside already-compiling generated code.
