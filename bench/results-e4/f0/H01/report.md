# panuy: sort by real distance (km), nearest first

## Root cause
`מרחק בקמ = sqrt(מרחק בריבוע)` compiled to `sqrt(_v[10])`. Slot 10 is itself a formula field,
which is never stored in the form array `_v`, so the km value was always `sqrt(0) = 0`.
Any formula that referenced another formula field had the same defect.

## Changes
1. `machtzev/generator/render-ds.mjs` — `compileFormula` now inlines a referenced formula field's
   own compiled expression (recursive, cycle-guarded via `seen`) instead of reading `_v[idx]`.
   Only pure arithmetic formulas inline; engine/conditional/rollup references keep old behavior.
   `labelIdx` carries `formula` so the compiler can see it.
2. `render-ds.mjs` — when an entity has a `| מיון:` sort, the list source gets `.toList()` so the
   in-place `rs.sort` no longer reorders the store's internal list (`appStore.records` returns it).
   Zero bytes change for entities without a sort.
3. `machtzev/generator/specs-ds/panuy.txt` — entity line gets `| מיון: מרחק בקמ עולה`;
   `[טבלה]` particle gets `| מיון: מרחק בקמ עולה`; fact-chip particle `מרחק בריבוע` → `מרחק בקמ`.
4. Regenerated: `node machtzev/generator/app-ds.mjs -f machtzev/generator/specs-ds/panuy.txt --name panuy --skin`.
5. `machtzev/pins.sha256` re-signed with `node machtzev/pins-check.mjs --write` (a repo hook forbids
   hand edits). It also refreshed pins that were already stale at HEAD (LEARNINGS.md, gates.tsv,
   particles.mjs, police.mjs, formula-fns.mjs, spec-lang-doc.mjs) — those files are untouched by me.
